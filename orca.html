Orca Desktop hoạt động thế nào?

Một môi trường vận hành đội AI coding agent: từ Git worktree, terminal và chat đến remote runtime, orchestration và khả năng kết nối lại.

Khám phá mô phỏng ↓So sánh Paperclip ↗

Tổng hợp tài liệu Orca và cấu trúc repository công khai, 18/11/2026. Các sơ đồ là diễn giải kiến trúc; mọi ID, sự kiện và output mô phỏng đều giả lập.

01 / Hệ thống

Client không phải là tiến trình agent

Orca là ADE (Agent Development Environment), không phải model. Agent dùng CLI và tài khoản/provider riêng; Orca cung cấp workspace, lớp quản lý phiên, tương tác và điều phối.

01

Client

Desktop, mobile, CLI và client đã pair. Hiển thị terminal/chat, gửi lệnh và theo dõi kết quả.

02

Orca runtime

Quản lý workspace, terminal handle, agent identity, điều phối, routing và trạng thái. Headless có orcad.

03

Execution host

Terminal daemon/relay giữ PTY; OS thực thi shell và agent CLI. Workspace và credential nằm ở môi trường thực thi thích hợp.

Hai đường thông tin khác nhau

Terminal stream: ký tự, escape sequences, resize, screen và scrollback. Tốt cho TUI tương tác; không phải transcript có cấu trúc.

Agent identity & events: hooks và OSC title giúp nhận biết trạng thái ở agent được hỗ trợ. Agent read đọc hội thoại/transcript, khác terminal read.

Không mô tả mọi agent qua ACP hay JSONL. Orca có cả chat và terminal agent; cơ chế cụ thể tùy loại agent. JSON của Orca CLI là API output của Orca, không đồng nghĩa stdout của agent là JSON.

Ranh giới bảo mật

Pairing cấp quyền vào runtime; SSH là kết nối host; credential model là quyền riêng của agent. Worktree cô lập nhánh/file làm việc, không tự tạo sandbox OS.

      03 / CLI anatomy

      Orca thao tác với agent thế nào?

      CLI điều khiển một runtime đang chạy. Có thể tạo workspace, launch agent, đọc terminal, gửi input và dùng orchestration để gửi thông điệp có định danh.

      Launch và quan sát TUI

      Nếu đã dùng --agent, không khởi chạy trùng. Kiểm tra terminal handle và host trước khi gửi input.
      Đọc hội thoại và gửi message
      orca agent list --json
orca agent read orca_session_id:<id> --json
orca orchestration send --to '<address>' \
  --subject 'Status' --body 'Status?' --type question
      Agent read đọc transcript khi Orca biết vị trí của nó. Dùng orchestration send khi muốn gửi thông điệp cho agent theo địa chỉ, thay vì gõ phím vào TUI.

      PTY / terminal readStream hoặc screen; input, resizeKhông suy diễn tool events từ text một cách chắc chắn
      Agent hooks / OSCTín hiệu trạng tháiAgent không hỗ trợ có thể unknown
      Agent readTranscript / chat historyKhác history terminal; có thể thiếu khi chưa ghi
      OrchestrationMessage, task, dispatch, workerKhông đồng nghĩa mọi thao tác đều là terminal send
      

      04 / Runtime boundaries
      Ba cách chạy, ba vị trí quản lý
      Local desktop
      Runtime và process ở máy desktop. PTY do daemon quản lý; đóng UI không nhất thiết kết thúc terminal.
      SSH worktree
      Desktop sở hữu runtime; SSH host thực thi workspace/terminal qua relay. Mất kết nối không phải bằng chứng process chết.
      Remote Orca Server
      Máy server sở hữu runtime, workspace và session. Desktop/mobile là client đã pair. orca serve dùng orcad mặc định, có ngoại lệ macOS.
      Service supervision
      orca serve
orca serve --supervise
# Linux: service user unit (systemd)
# macOS: LaunchAgent
      Supervisor restart runtime với backoff. Terminal daemon có lifecycle khác; systemd cgroup isolation ảnh hưởng terminal có sống qua restart service hay không.
      Phân biệt các identity
      Workspace: nơi làm việc. PTY: phiên OS/terminal. Handle: định danh theo runtime, có thể stale. Orca session ID: định danh agent theo host. Provider session: ngữ cảnh riêng của CLI khi hỗ trợ.
      Không đồng nhất PID, handle và session ID. Sau runtime restart, liệt kê lại handle; không gửi cùng prompt vào cả handle cũ và mới.
      Idle có phải task hoàn thành?
      Không. TUI có thể chờ input hoặc kết thúc lượt mà chưa đạt yêu cầu. Kiểm tra transcript, diff, test và trạng thái công việc.
      Đóng terminal khác sleep hay detach thế nào?
      Close chủ động dừng process và loại terminal; sleep là cơ chế lưu để mở lại khi phù hợp. Detach/mất client không chứng minh PTY đã dừng; khả năng phục hồi phụ thuộc host và cấu hình.
      Agent có thể điều khiển agent khác?
      Có thể dùng Orca CLI với workspace/terminal selector và orchestration để tạo worker, định tuyến thông điệp, đọc trạng thái. Dùng dispatch theo dõi công việc thay cho việc chỉ gửi phím không có identity.
      

      05 / Design implications
      Orca, Paperclip và Alpha
      Đây là so sánh định hướng và đề xuất, không phải mô tả những gì Alpha đã triển khai. Paperclip thiên về công việc và tổ chức; Orca nhấn mạnh môi trường vận hành agent nhưng cũng có orchestration.

      ControlRuntime + orchestrationTask, heartbeat, policySupervisor
      ExecutionTerminal daemon, relay, agent CLI/chatAdapter / native runnerController + driver registry
      IdentityWorkspace, handle, Orca sessionAgent, task, run, provider sessionHost / app / process / session / task ID riêng
      ScopeAgent development environmentAgent organizationMọi app quản lý được, kể cả systemd
      Alpha SupervisorDesired state · policy · task
      ↓ ↑
      Alpha ControllerInventory · lifecycle · observed state
      ↓ ↑
      App driverssystemd · process · container
      Agent adaptersPTY · JSON · ACP
      Điều nên học
      Giữ ownership của process tách khỏi UI; lưu identity bền vững và capability; phân biệt disconnect/exit; đọc trạng thái qua nhiều nguồn; tái attach thay vì launch trùng; dùng policy trước mọi hành động có side effect.
      Tên các lớp trong sơ đồ này là thiết kế đề xuất cho Alpha; không phải tên module chính thức của Orca.
